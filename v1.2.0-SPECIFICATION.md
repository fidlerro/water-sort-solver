# Water Sort Puzzle Solver v1.2.0 - Technical Specification

## Project Overview

Version 1.2.0 represents a complete modernization of the Water Sort Puzzle Solver, transitioning from Knockout.js to React with enhanced AI capabilities for mobile-first usage. This version introduces intelligent screenshot analysis that automatically detects tube configurations and handles advanced game mechanics including hidden/unknown colors.

**Target Platform**: Progressive Web App (PWA) optimized for mobile devices  
**Primary Framework**: React 18+ with TypeScript  
**AI Engine**: TensorFlow.js for image recognition and color detection  
**Release Date**: Q1 2026

---

## Executive Summary

The Water Sort Puzzle Solver v1.2.0 transforms the user experience by eliminating manual puzzle configuration. Users simply upload a screenshot of their game, and AI automatically:

- Detects the number of tubes (3-18 tubes)
- Identifies visible colors in each tube segment
- Recognizes hidden/unknown colors (marked as "?")
- Generates the puzzle configuration
- Solves the puzzle accounting for uncertainty

This version is specifically designed for advanced game levels where only the topmost color layer is visible, with lower layers remaining hidden until exposed through gameplay.

## Core Features

### 1. AI-Powered Screenshot Analysis

#### Image Upload

- Support for drag-and-drop or file picker
- Accept formats: JPG, PNG, WebP
- Client-side image preprocessing:
  - Auto-rotation correction
  - Brightness/contrast normalization
  - Noise reduction
  - Resize to optimal dimensions (max 1920x1080)

#### Tube Detection Algorithm

```typescript
interface TubeDetectionResult {
  numberOfTubes: number;
  tubeBoundingBoxes: BoundingBox[];
  tubeOrder: number[]; // Left-to-right, top-to-bottom
  confidence: number; // 0-1
}
```

**Detection Process**:

1. Convert image to grayscale
2. Apply edge detection (Canny algorithm)
3. Detect vertical rectangular shapes (tube containers)
4. Filter by aspect ratio (tubes are typically 1:3 to 1:5 height/width)
5. Sort tubes by position (left-to-right, top-to-bottom)
6. Return count and positions

#### Color Segment Detection

```typescript
interface ColorSegment {
  position: 0 | 1 | 2 | 3; // top to bottom
  color: string | "?"; // Hex color or unknown
  confidence: number;
}

interface TubeConfiguration {
  tubeIndex: number;
  segments: ColorSegment[]; // Array of 0-4 segments
}
```

**Detection Process**:

1. For each detected tube, extract image region
2. Divide tube vertically into 4 equal segments (bottom-to-top)
3. For each segment:
   - Extract dominant color using k-means clustering
   - Calculate color saturation and variance
   - If saturation < threshold OR variance > threshold → mark as "?"
   - If segment appears empty (matches background) → skip
   - Otherwise, normalize to nearest game color
4. Build configuration array

#### Color Palette Generation

```typescript
interface DetectedColor {
  hexColor: string;
  frequency: number; // How many segments use this color
  letter: string; // Auto-assigned A-P
  isComplete: boolean; // frequency === 4 or 0
}
```

**Process**:

1. Collect all detected colors from all tubes
2. Cluster similar colors (using Delta E color difference)
3. Assign letter codes (A-P) based on frequency
4. Generate color palette for solver

### 2. Hidden Color Handling ("?" Segments)

#### Data Model

```typescript
type ColorValue = string | "?"; // Hex color or unknown

interface PuzzleState {
  tubes: ColorValue[][]; // Array of tubes, each tube has array of colors
  knownColors: Set<string>; // All colors seen so far
  possibleColors: string[]; // Colors that could be in "?" segments
}
```

#### Solver Strategy for Unknown Colors

**Approach**: Generate multiple possible configurations and find common solution steps

```typescript
interface SolverResult {
  hasSolution: boolean;
  guaranteedMoves?: Move[]; // Moves that work for ALL possible configs
  confidence: "high" | "medium" | "low";
  alternativeStrategies?: string[]; // If guaranteed moves not available
}
```

**Algorithm**:

1. Identify all "?" positions
2. Generate possible color permutations for unknowns:
   - Use known colors that haven't reached frequency 4
   - Limit permutations to manageable number (e.g., top 100 most likely)
3. Solve each permutation independently
4. Identify moves that appear in ALL solutions (guaranteed safe moves)
5. Return guaranteed moves as initial strategy
6. Provide guidance for exposing hidden colors if no guaranteed moves exist

**Example Strategy**:

```
If unknowns exist:
- First, look for moves that only involve known colors
- Recommend moves that expose hidden colors safely
- After user makes move, allow re-analysis with updated info
```

## AI Implementation Details

### TensorFlow.js Models

#### Option 1: Custom Color Detection Model

Train a lightweight CNN to:

- Input: Tube segment image (64x64 RGB)
- Output: Color class (A-P) or "unknown" + confidence score

**Training Data**:

- Screenshots from various Water Sort games
- Labeled tube segments with color classes
- Augmentation: brightness, rotation, noise

#### Option 2: Traditional CV Approach (Recommended for v1.2.0)

Use computer vision without heavy ML:

1. **Tube Detection**: Contour detection + shape filtering
2. **Color Extraction**: K-means clustering on segment pixels
3. **Unknown Detection**: Statistical analysis of color variance
4. **Color Matching**: Color distance (Delta E) to known palette

```typescript
async function analyzeScreenshot(
  imageFile: File,
): Promise<PuzzleConfiguration> {
  // 1. Load and preprocess image
  const img = await loadImage(imageFile);
  const preprocessed = preprocessImage(img);

  // 2. Detect tubes
  const tubes = detectTubes(preprocessed);

  // 3. For each tube, detect color segments
  const configurations: TubeConfig[] = [];
  for (const tube of tubes) {
    const segments = extractSegments(tube);
    const colors = segments.map((seg) => detectColor(seg));
    configurations.push({
      index: tube.index,
      colors: colors,
    });
  }

  // 4. Generate color palette
  const palette = generatePalette(configurations);

  // 5. Return configuration
  return {
    version: "1.2.0",
    timestamp: new Date().toISOString(),
    tubes: configurations,
    colorPalette: palette,
    hasUnknowns: configurations.some((t) => t.colors.includes("?")),
    metadata: {
      source: "ai",
      confidence: calculateOverallConfidence(configurations),
    },
  };
}
```

### Color Detection Algorithm

```typescript
function detectColor(segmentImage: ImageData): ColorValue {
  // 1. Get dominant colors using k-means
  const dominantColors = kMeansClustering(segmentImage, (k = 3));
  const primaryColor = dominantColors[0];

  // 2. Check if segment is empty (matches tube background)
  if (isBackgroundColor(primaryColor)) {
    return null; // Empty segment
  }

  // 3. Calculate color confidence
  const saturation = getColorSaturation(primaryColor);
  const variance = getPixelVariance(segmentImage);

  // 4. Determine if unknown
  if (saturation < SATURATION_THRESHOLD || variance > VARIANCE_THRESHOLD) {
    return "?";
  }

  // 5. Map to nearest game color
  const nearestColor = findNearestGameColor(primaryColor, knownGameColors);
  return nearestColor;
}

const knownGameColors = [
  { letter: "A", hex: "#FF0000", name: "Red" },
  { letter: "B", hex: "#0000FF", name: "Blue" },
  { letter: "C", hex: "#00FF00", name: "Green" },
  // ... etc
];
```

### Unknown Color Solver Strategy

```typescript
function solveWithUnknowns(config: PuzzleConfiguration): Solution {
  const unknownPositions = findUnknownPositions(config);

  if (unknownPositions.length === 0) {
    // No unknowns, solve normally
    return standardSolve(config);
  }

  // Generate possible configurations
  const possibleConfigs = generatePossibleConfigurations(
    config,
    unknownPositions,
    maxPermutations: 50
  );

  // Solve each configuration
  const solutions = possibleConfigs.map(cfg => standardSolve(cfg));

  // Find common moves across all solutions
  const guaranteedMoves = findCommonMoves(solutions);

  if (guaranteedMoves.length > 0) {
    return {
      steps: guaranteedMoves,
      totalMoves: guaranteedMoves.length,
      confidence: 'medium',
      warnings: [
        `${unknownPositions.length} unknown colors detected`,
        'These moves are safe for all possible configurations'
      ]
    };
  }

  // No guaranteed moves - provide strategy
  return {
    steps: [],
    totalMoves: 0,
    confidence: 'low',
    warnings: [
      'Cannot determine guaranteed moves with current unknowns',
      'Suggestion: Make moves that expose hidden colors',
      'Then re-upload screenshot for updated analysis'
    ]
  };
}
```

## User Flows

### Primary Flow: Screenshot Upload to Solution

1. **User opens app**
   - Sees upload zone prominently displayed
   - Optional: See cached recent puzzles

2. **User uploads screenshot**
   - Drag & drop or tap to select file
   - Loading indicator appears

3. **AI analyzes screenshot** (2-5 seconds)
   - Progress indicator with steps:
     - "Detecting tubes..."
     - "Analyzing colors..."
     - "Building configuration..."
4. **Review detected configuration**
   - Show visual preview of detected tubes
   - Display confidence score
   - Allow quick edits if needed
   - "Looks Good ✓" or "Adjust Manually"

5. **Solve puzzle**
   - Automatic transition to solver
   - Display solution steps
   - Show warnings if unknowns present

6. **Navigate solution**
   - Swipe or tap to step through
   - Visual representation updates
   - Move descriptions shown

7. **Complete or retry**
   - Save to history
   - Upload new screenshot
   - Share solution

### Secondary Flow: Manual Configuration

1. User taps "Setup Manually"
2. Specify number of tubes
3. For each tube, input color codes or tap color picker
4. Mark unknowns with "?" symbol
5. Tap "Solve"
6. Continue to solution viewer
